Шаблоны и пагинация

Собрали каркас один раз — рендерим любые значения. Плюс готовый бесстейтовый пагинатор.

Когда одно и то же сообщение нужно отправить много раз (страницы, товары, отчёты), держать в памяти полные payload'ы избыточно, а парсить текст обратно — хрупко. Вместо этого собирается шаблон с слотами (сентинелами), а при каждом ответе меняются только значения. Оба модуля — на этом же принципе; оба не мутируют исходный каркас.

Подключение

Модули живут в отдельных entrypoint и не входят в корневой импорт:

ПакетЧто внутри
discordjs-components-v2/lib/template V2Template
discordjs-components-v2/lib/pagination V2Paginator
discordjs-components-v2/lib/advanced keepOnly, moveByKind

V2Template

Каркас сообщения собирается один раз (из new V2Builder(), raw-компонентов или любого входа V2Builder.parse — в т.ч. сообщения). Слоты регистрируются с сентинелом: без явного сентинела slot("name") даст токен {{name}}. render() подставляет значения во все TextDisplay и в обычный content сообщения, возвращая свежий V2Builder.

ts
import { V2Builder } from "discordjs-components-v2";
import { V2Template } from "discordjs-components-v2/lib/template";

const tpl = new V2Template(new V2Builder()
  .content("Показываю: {{n}}")          // слот и в plain-контенте тоже
  .text("Привет, {{name}}!")
  .buttons({ id: "like", label: "👍" }));

tpl.slot("name");                       // авто-сентинел {{name}}
tpl.slot("n");                          // → {{n}}

// рендер никогда не мутирует каркас — можно звать без ограничений
const payload = tpl.render({ name: "Мир", n: 42 }).build();
// content: "Показываю: 42", первый TextDisplay: "Привет, Мир!"

// из существующего сообщения:
const tpl2 = V2Template.parse(fetchedMessage);
tpl2.slot("content");
await tpl2.render({ content: "новая страница" }).send(ctx);
МетодЧто делает
new V2Template(input?)builds на базе builder / raw-компонентов / message-подобного входа
V2Template.parse(input)то же, что и конструктор — удобно как статик
.slot(key, sentinel?)регистрирует слот; без сентинела — {{"{{key}}"}}
.slots({ key: sentinel })регистрирует несколько сразу
.sentinelOf(key) · .slotKeys()сентинел / список ключей
.render(values)→ новый V2Builder с подставленными значениями
.build()валидирует и возвращает payload каркаса (без подстановки)
.builderлежащий в основе V2Builder
ℹ️ undefined не трогает сентинел

render({ x: undefined }) оставляет {{x}} на месте — удобно делать частичный рендер. Строки и числа приводятся к строке.

V2Paginator

Бесстейтовый пагинатор поверх шаблона. Страницы — это slot-значения для общего шаблона (или готовые V2Template — тогда общий не нужен). Вниз добавляется один ряд кнопок pag:0, pag:1, … (текущая выделена примарным стилем и задизаблена). Текущая страница читается из самого сообщения — никакого кэша.

ts
import { V2Builder } from "discordjs-components-v2";
import { V2Template } from "discordjs-components-v2/lib/template";
import { V2Paginator } from "discordjs-components-v2/lib/pagination";

const tpl = new V2Template(new V2Builder().text("{{body}}")).slot("body");

const pages = new V2Paginator({
  template: tpl,                                  // обязателен, если pages — slot-мапы
  pages: [
    { body: "Страница 1" },
    { body: "Страница 2" },
    { body: "Страница 3" },
  ],
  pageButton: "pag",                              // → custom_id `pag:0`, `pag:1`, …
  pageLabel: (i, total) => `${i + 1} / ${total}`, // метки кнопок (по умолчанию "1", "2", …)
});

await interaction.reply(pages.render(0));         // payload первой страницы

Обработчик кнопок — один вызов. Достаточно custom_id с номером страницы; вручную можно расширить и стрелками (pag:prev/pag:next):

ts
import { Discord, Button } from "discordx";
import type { ButtonInteraction } from "discord.js";
import { V2Paginator } from "discordjs-components-v2/lib/pagination";

@Discord()
class PaginationHandler {
  @Button({ id: /^pag:/ })
  async paginate(interaction: ButtonInteraction) {
    // сам сделает update() / editReply() / reply() и вернёт true,
    // если custom_id принадлежит этому пагинатору
    await pages.jump(interaction);
  }
}
Метод / опцияЧто делает
new V2Paginator({ pages, pageButton, template?, pageLabel? })конструктор; до 5 страниц (один ряд кнопок)
.render(page)payload страницы + ряд кнопок; вне диапазона — throw
.jump(ctx)true, если обработал; принимает и discordx-ctx (ctx.interaction)
.currentFromMessage(msg)номер задизабленной кнопки (источник истины текущей страницы)
.size · .pageButtonколичество страниц / префикс custom_id
💡 Почему без кэша

Пагинатор ничего не помнит: номер текущей страницы всегда custom_id той кнопки, которая disabled в текущем сообщении. Переключение = объявить новый custom_id задизабленным и подставить контент страницы — ровно то, что делает render().

Редкие операции: lib/advanced

Два инструмента намеренно держатся вне корневого index: keepOnly (оставить в дереве только совпавшее с селектором + их предков) и standalone moveByKind. Оба работают in place, поэтому требуют «свой» (нормализованный) массив. Явный пример keepOnly ниже:

ts
import { keepOnly, moveByKind } from "discordjs-components-v2/lib/advanced";

const children = V2Builder.parse(message).toJSON().components; // owned
keepOnly(children, /розыгрыш/i);   // оставить только совпавшее (+ предков)
moveByKind(children, "section", 2, 0); // переместить секцию наверх
⚠️ In place

keepOnly / moveByKind мутируют переданный массив. Если нужна защита от побочных эффектов — предварительно cloneDeep/toJSON() или используйте методы билдера/редактора (см. «Секции и layout»), которые работают на своих данных.
