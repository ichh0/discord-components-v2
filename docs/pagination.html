📄Пагинация вручную

Pattern

Пагинация

Меняем контент в сообщении кнопками — без кэшей и без хрупкого парсинга больших текстов.

Сложность пагинации не в кнопках и не в деревьях — а в одном: содержимое страниц может быть большим и непредсказуемым. Парсить такой текст назад, чтобы найти, что менять — хрупко. Хранить в себе полные payload'ы каждой страницы — расточительно.

⚡ Готовый класс: V2Paginator

В библиотеке есть встроенная бесстейтовая реализация на тот же принцип («страница = шаблон + слоты», текущая страница читается из задизабленной кнопки):
import { V2Paginator } from "discordjs-components-v2/lib/pagination";
import { V2Template } from "discordjs-components-v2/lib/template";
Достаточно одного вызова await pages.jump(ctx) в обработчике кнопок pag:N / pag:prev / pag:next. Подробная документация — на странице Шаблоны и пагинация. Эта страница показывает механику вручную — полезно, когда нужно больше контроля.

Решение — шаблон + сентинел:

🏗️

Каркас один

Структура (секция, текст, разделитель, кнопки) собирается один раз и не меняется.

🔁

Сентинел

В текст вшивается токен {{__CONTENT}}. Замена детерминированная.

🧮

Стейт в кнопке

Текущая страница живёт в custom_id индикатора. Кэш не нужен.

📄

Только контент в памяти

Хранится лишь массив коротких строк страниц — не payload'ы целиком.

Сборка шаблона

ts
const pages = [
  "# Обновление 2.2\n*Список изменений на этой странице*...",
  "# Обновление 2.2\n**Исправления багов**...",
  // ... ещё страницы
];

// Собираем каркас один раз:
const frame = new V2Builder()
  .section({ title: "📄 Пагинация", thumbnailUrl: thumb })
  .text("{{__CONTENT}}")            // ← слот
  .separator("large")
  .buttons(
    { id: "pag:prev", label: "◀ Назад", style: "Primary" },
    { id: "pag:1", label: "1 / 3" },  // индикатор, в custom_id — номер страницы
    { id: "pag:next", label: "Вперёд ▶", style: "Primary" },
  );

await frame.send(interaction);

Обработчик кнопки

ts
import { Discord, Button } from "discordx";
import type { ButtonInteraction } from "discord.js";
import { V2Builder } from "discordjs-components-v2";

@Discord()
class Pagination {
  @Button({ id: /^pag:/ })
  async paginate(interaction: ButtonInteraction) {
    const builder = V2Builder.parse(interaction.message); // каркас в билдер

    // Текущая страница из custom_id индикатора
    let current = 0;
    for (const b of builder.findAll(/^pag:\d+$/)) {
      current = Number(b.component.custom_id.split(":")[1]) - 1;
    }

    const next = interaction.customId.endsWith("next")
      ? Math.min(current + 1, pages.length - 1)
      : Math.max(current - 1, 0);

    if (next === current) return; // на границе — ничего не делаем

    // Единственное изменение — контент слота
    builder.replaceText("{{__CONTENT}}", pages[next]);

    // Обновляем индикатор текущей страницы
    builder.setButtonLabel(`pag:${current + 1}`, `${next + 1} / ${pages.length}`);

    // Границы обрабатываем в полной версии ниже
    // …
    await builder.send(interaction); // update
  }
}
⚠️ Упрощение ради наглядности

В примере выше пометка задизабленных кнопок сокращена. Ниже — корректная версия без ухищрений:

ts
    // Границы: на первой странице выключаем «Назад», на последней — «Вперёд»
    builder.enableButtons(["pag:prev", "pag:next"]);
    if (next === 0) builder.disableButtons("pag:prev");
    if (next === pages.length - 1) builder.disableButtons("pag:next");

И весь обработчик целиком с корректной границей:

ts

Почему это не ломается

  • Структура не парсится. parse восстанавливает каркас целиком; мы лишь меняем текст по точному токену.
  • Контент никогда не парсится обратно. Он всегда лежит в массиве pages, а в сообщении — только текущая страница.
  • Ноль кэша payload'ов. Единственный стейт — короткий номер страницы в custom_id.
  • Любой контент. Раз страница попадает в слот строкой — она может быть какой угодно.

Обобщение на «страницы с разной структурой»

Если каждая страница — другой набор секций/галерей, то вместо одного слота можно держать горячий билдер для текущей страницы, а «скелет» восстанавливать заново при каждом переключении. Сентинельная замена подходит именно там, где меняется только текст — а это самый частый случай.

💡 Рекомендация

Раз у вас «слои» (секция → текст → сепаратор → кнопки), вынесите сборку каркаса в одну функцию buildFrame(pageIndex: number) и вызывайте её и при первом ответе, и в обработчике кнопки. Тогда у вас вообще не будет сентинела — просто пересборка. Оба подхода валидны; сентинел эффективнее, когда текст большой.
