Валидация

Ловим лимиты и невалидные деревья до отправки в Discord.

build() проверяет документированные лимиты Discord и кидает понятную ошибку со списком всех проблем. Отдельно функцию можно вызвать напрямую:

ts
import { validateComponents } from "discordjs-components-v2";

const result = validateComponents(someComponents);
// { valid: boolean, errors: string[] }

if (!result.valid) {
  console.error(result.errors.join("\n"));
}

Что проверяется

ПроверкаЛимит
Компонентов всего≤ 40
Детей контейнера≤ 10 на уровне
Текстовых блоков в секции≤ 3
Компонентов в ActionRow1–5
Кнопкиобязательные поля: custom_id или url/sku_id; label/emoji — у обычных
Селектыобязательные поля, корректные options
Секцииобязательно ∃ текст + аксессуар
ActionRowне пустой (иначе Discord отвергает)

Пример ошибки

ts
const builder = new V2Builder()
  .buttons(
    { id: "1", label: "A" },
    { id: "2", label: "B" },
    { id: "3", label: "C" },
    { id: "4", label: "D" },
    { id: "5", label: "E" },
    { id: "6", label: "F" }, // 6-я кнопка в ряду
  );

builder.build();
// throws: Invalid components:
// - Buttons: 6 in one action row — maximum is 5

Валидация модалок

V2ModalBuilder.build() дополнительно проверяет: наличие title и custom_id, дубликаты customId полей, minLength > maxLength, minValues > maxValues и пользовательские правила из .rule(). Подробнее — на странице Модальные окна.

ℹ️ Когда валидация «ломает»

Парсер (parseComponents/editComponents) валидацию не запускает — он принимает любой JSON, включая будущие/недокументированные поля. Валидация вызывается только в момент сборки (build) и напрямую через validateComponents.
