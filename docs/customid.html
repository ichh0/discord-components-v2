customId и состояние

Компоненты без кэша = состояние живёт в самом custom_id.

Одно из следствий философии «без кэшей»: данные, которые нужны обработчику кнопки, должны быть доступны из самой кнопки. CustomIdBuilder — однострочный кодек формата name:entityId:executorId:rest… (разделитель всегда :) с гарантией лимита Discord в 100 символов.

ts
import { CustomIdBuilder, CustomIdError } from "discordjs-components-v2";

const id = CustomIdBuilder.build({
  name: "_modal",
  entityId: "x7k",
  executorId,             // "" → пропускается («нет сущности»)
  rest: ["p", "2"],       // если нужно больше данных — массив сегментов
});
// "_modal:x7k:555:p:2" — всегда ≤ 100 символов

const { name, entityId, executorId } = CustomIdBuilder.parse(id);
CustomIdBuilder.is(id, "_modal"); // true → быстрый роутинг без if/else

API

Метод / константаЧто даёт
.build(parts)собрать id; кидает CustomIdError при пустом имени, : внутри сегмента или переполнении >100 символов (с числом «сократить на N»)
.parse(customId)lenient-разбор { name, entityId, executorId, rest, raw, length } — никогда не падает
.is(customId, name)валидность + совпадение имени (готово для роутера)
.isValid(customId)true только если ≤100 символов и есть имя
.capacityOf(parts) / .remaining(parts)занято / свободно символов до лимита
CUSTOM_ID_MAX_LENGTHконстанта 100
CustomIdErrorотдельный класс ошибок

Роутинг обработчиков

Типичная схема в discordx — один обработчик на группу кнопок:

ts
@Button({ id: /_.+/ })
async handle(interaction: ButtonInteraction) {
  const id = CustomIdBuilder.parse(interaction.customId);

  if (id.entityId !== draftId) return;      // чужая сущность
  if (id.executorId !== interaction.user.id) {
    return interaction.reply({ content: "Это не твоя кнопка", ephemeral: true });
  }

  if (CustomIdBuilder.is(interaction.customId, "_nabor")) {
    // …обработка
  }
}
